# Переезд моста на постоянный сервер (старый ноут)

Чек-лист, чтобы старый ноут стал всегда-включённым сервером Assi, а основной остался рабочим.

## 1. Что нужно на ноуте-сервере

- Windows 10/11, включён вход без пароля или автологин (иначе после перезагрузки мост не поднимется).
- Python 3.10+ и [OpenCode](https://opencode.ai), авторизованный в модели.
- Node/npm не нужен, всё ставит `install-assi.ps1`.

```powershell
git clone https://github.com/F0RN1/assi-bridge.git
cd assi-bridge
powershell -ExecutionPolicy Bypass -File install-assi.ps1 -Autostart
```

`-Autostart` кладёт ярлык в автозагрузку — после перезагрузки мост поднимется сам.

## 2. Питание и сон

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 10
powercfg /hibernate off
```

Также в «Электропитание → Действие кнопки питания» выключить сон по закрытию крышки, если ноут будет закрыт.
В BIOS: **Wake on LAN = Enabled**, «Power on after power loss» = On (на случай сбоя питания).

## 3. Сеть

- Лучше закрепить IP в роутере (DHCP reservation) по MAC ноута.
- Порт моста — `8787`; проверка: `http://127.0.0.1:8787/api/ping` → `{"ok":true}`.
- Открыть порт в брандмауэре для локальной сети:
  `netsh advfirewall firewall add rule name="Assi 8787" dir=in action=allow protocol=TCP localport=8787`

## 4. Туннель (доступ из интернета)

Вариант А — переиспользовать текущий туннель: скопировать `%USERPROFILE%\.cloudflared\config.yml` и JSON-креды, на новой машине запустить `cloudflared tunnel run`.
Вариант Б — новый туннель: `cloudflared tunnel create assi-server`, прописать ingress на `http://127.0.0.1:8787`, DNS-запись CNAME в панели Cloudflare.

В конфиге обязательно:

```yaml
protocol: http2
edge-ip-version: "4"
```

## 5. Токен и приложение

- Токен генерируется сам и лежит в `bridge.json` (в репозиторий не попадает).
- Перенести можно копированием `bridge.json` — тогда приложение продолжит работать без перенастройки.
- Либо оставить новый токен и в приложении нажать «Сменить сервер», ввести адрес и новый токен.

## 6. Wake-on-LAN

- MAC нового ноута: `getmac /v` → «Физический адрес» активного адаптера.
- В приложении MAC подхватывается сам при открытии чата (`/api/wol-info`), но проверить стоит: выключить ноут, нажать в приложении «Разбудить (WOL)».
- Работает только из той же локальной сети (широковещательный пакет не проходит через интернет).

## 7. Выключение и перезагрузка

По умолчанию эти кнопки скрыты (`ASSI_POWER_ACTIONS=wake,sleep,lock`).
На сервере, который не жалко, их можно включить:

```powershell
$env:ASSI_POWER_ACTIONS = "wake,sleep,lock,reboot,shutdown"
```

и прописать в ярлыке автозагрузки, иначе после перезапуска настройка сбросится.

## 8. Проверка после переезда

1. `http://127.0.0.1:8787/local` — карточка экземпляра, статус «отвечает».
2. `https://<домен>/api/ping` — `{"ok":true}`.
3. На телефоне: сообщение в чат → ответ; отправка фото; лист питания; WOL после выключения.
4. Перезагрузить ноут-сервер и убедиться, что мост поднялся сам (автозагрузка).
